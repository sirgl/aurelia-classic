## Performance first (a principle, not a section)

Performance is part of the Definition of Done of every slice, not a separate stage:
counters gate (§49 of platform/project.md), wall time is only noise. Rules:

- Every slice brings perf case(s) for the new functionality
  (sim: `perf_baseline`, render: `render_baseline`).
- Every slice ends with `CHECK-OK: all counters match` plus an explanation
  of counter shifts in `BASELINE.md` (wall-time deltas without an explanation are a failure).
- Budgets (see below) are checked at every milestone; exceeding one is a
  release blocker for the milestone, not "we'll optimize later".
- Allocations: 0 per frame in steady state (buffers/heightfield cached),
  0 per call in hot paths (WorkedSet style: stack instead of Vec).
  A new allocation in a hot path is allowed only with a before/after measurement.
- Heavy systems (AI turn, regeneration) are incremental by construction
  (oracle pairs §62 of platform/project.md), a full rebuild is only a fallback/oracle.

### Why there is no tree (history)

Technologies were introduced as a minimal add-on to the modifier pipeline:
we needed a consumer for MultiplyYield (+10%) and a reason to gate content
(a granary behind pottery). Hence: 3 techs as a flat list, learning is instant
and free, no beakers/costs/dependencies. A real tree is A2,
and it deliberately waited for the income economy (the "empire pool" pattern was first
run in on gold in A1, then reused for beakers).

### Spec of A2 — IMPLEMENTED (v18; remainders above)

- Science income: +1 beaker per citizen?/building (library), player pool, stockpile.
- Tech price from content (`cost`, as for units/buildings — ZeroCost is rejected).
- Dependencies: `requires: [keys]` in SourceTechnology, the compiler checks
  acyclicity and known keys (UnknownReference/ForbiddenCycle already exist).
- Research: the current tech + a queue per player (ChooseTechnology takes
  the next available one; an unavailable one without prerequisites is an honest error).
- Eras by tree depth (Ancient/Classical/…), era bonus — later.
- UI: top-bar buttons → the tree (nodes + arrows + progress), queue.
- AI: priority weights (military/economy by situation) — a minimum in E1.
- Eurekas — a separate sub-item afterwards (triggers already exist in effects.rs).

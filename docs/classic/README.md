## Edition and sources

The rule set is a **rule set derived from Unciv (its Gods & Kings rule files plus own extensions)**. Standard speed, Standard map size, Prince difficulty unless stated otherwise.

The only permitted source is **Unciv** (<https://github.com/yairm210/Unciv>, MPL-2.0: its JSON rule files and its Kotlin code). Unciv has the Vanilla and Gods & Kings rule sets and nothing for the later expansion-only systems, so:

- an entry that Unciv has carries `"provenance": "unciv: <File>.json, <entry>"` and the list of the fields taken from Unciv in `unciv_fields`;
- an entry that Unciv does not have (expansion-only additions, our own extensions) carries `"provenance": "own value, unverified"`;
- the catalogs are written by [`tools/import-unciv.py`](../../tools/import-unciv.py) from a read-only checkout of Unciv; the result is committed; [UNCIV-ATTRIBUTION.md](UNCIV-ATTRIBUTION.md) lists each derived file with its Unciv file; RESOURCING.md is the re-sourcing record; SOURCES.md is the older inventory of where the data came from before the re-sourcing.

## Conventions

**Identifiers.** The key style of the content and art catalogs: `core:<kind>/<slug>`, the slug is the English name. 

| Kind | Example | Matches the art catalog |
|---|---|---|
| `core:tech/` hyphens | `core:tech/drama-and-poetry` | `research-units/atlas-index.tsv` (same id) |
| `core:unit/` hyphens | `core:unit/great-war-infantry` | `bnw:unit/<slug>` → field `art_id` |
| `core:building/` underscores, including wonders | `core:building/great_library` | `bnw:building/`, `bnw:world_wonder/`, `bnw:national_wonder/<slug>` → `art_id` |
| `core:project/` underscores | `core:project/apollo_program` | `bnw:project/<slug>` |
| `core:policy/<branch>`, `core:policy/<branch>/<policy>`, `…/opener`, `…/finisher` | `core:policy/tradition/legalism` | `policies/catalog.tsv` (`tradition/legalism`) |
| `core:belief/<category>/<slug>` | `core:belief/pantheon/god-of-war` | `religion/inventory.tsv` (`belief/pantheon/god-of-war`) |
| `core:nation/<slug>` | `core:nation/aztecs` | `nations/completion-catalog.tsv` (slug) → `art_slug` |
| `core:resource/` underscores | `core:resource/gold` | — |
| `core:improvement/`, `core:terrain/`, `core:feature/`, `core:natural-wonder/`, `core:promotion/`, `core:city-state/`, `core:era/`, `core:specialist/`, `core:religion/` | `core:improvement/lumber-mill` | — |
| Service kinds: `core:unit-class/`, `core:building-class/`, `core:unit-combat/`, `core:domain/`, `core:build/`, `core:trait/`, `core:leader/` | `core:unit-combat/mounted` | — |

Service kinds are enumerations without a separate catalog: a member corresponds to a game type one to one (`core:unit-class/musketman`, `core:build/farm`), and every entity has a `class` field. A reference to a class (`upgrades_to`, `replaces`, an effect target) resolves to the default unit or building of that class; a nation with a unique variant substitutes its own.

**Numbers.** Prices are the base values of the tables at Standard speed (game speed 100%), before the multipliers of difficulty, start era, number of cities and map size. Technologies on a Standard map cost ×1.10 (map size multiplier 110%), plus the city penalty — see the technology cost in `rules.md`. Worker build time (`build.work_time`) is in hundredths: 700 = 7 worker turns. Percentages are written as in the game: 25 = +25%.

**Effects.** Each effect is a record:

```json
{"scope": "city", "selector": {"kind": "tiles_of_city", "filter": {"feature": "core:feature/jungle"}},
 "condition": null, "trigger": "passive", "modifier": "tile.yield.science.flat", "amount": 2,
 "target": "…optional, id of the target…", "needs_mechanic": "…only if a simple modifier is not enough…",
 "source": "own value, unverified"}
```

- `scope` — the owner of the effect: `city`, `player`, `unit`, `tile`, `religion`.
- `selector.kind` — what it acts on; `filter` narrows it (building, resource, feature, unit class, domain, specialist, great person). The full list is in `effect_vocabulary.json`. Key ones: `this_city`, `all_cities`, `capital`, `coastal_cities`, `tiles_of_city`, `tiles_of_player`, `specialists_of_city`, `buildings_of_player`, `units_trained_here`, `all_units`, `this_unit`, `following_cities` (cities with this religion in the majority), `religion_founder`, `holy_city`, `city_states`.
- `trigger` — when it applies: `passive` (while the condition holds), `on_complete`, `on_adopt`, `on_research`, `on_unit_trained`, `on_kill`, `on_city_founded`, `on_great_person_expended`, etc.
- `modifier` — what changes. Families: `yield.<yield>.flat|pct|per_pop`, `tile.yield.<yield>.flat`, `building.yield.<yield>.flat`, `specialist.yield.<yield>.flat`, `happiness.*`, `unhappiness.*`, `combat.*.pct`, `unit.*`, `heal.*`, `production.*.pct`, `great_people.rate.pct`, `trade.*`, `tourism.*`, `city.*`, `border.*`, `grant.*` (grant a building, unit, technology, policy, promotion; the target is in `target`), `unlock.*`. The order of evaluation follows the kernel spec (§21): base → flat → additive percentages → multipliers → limits → rounding.
- `needs_mechanic` — the effect does not reduce to a simple modifier and requires a separate M4 mechanic. This marks boolean flags (`trait.fight_well_damaged`, `building.border_obstacle`) and numeric columns of special mechanics (`trait.unique_luxury_cities`). The modifier of such an effect keeps the name of the game's column: `…Modifier`/`…Mod` — percentages, `…Change` — a flat value.
- `"modifier": "text_only"` with `needs_mechanic: "hardcoded_<type>"` — the entity has no data, the behavior is hardwired in the game's code; the description is in the `text` field.
- `source` — where the effect comes from: `unciv: <File>.json` (confirmed against Unciv) or `own value, unverified`.
- Entities carry no description text: the encyclopedia describes them from their typed effects.

**Uncertainty marks.** `"provenance": "own value, unverified"` on an entry, `"source": "own value, unverified"` on an effect. In the code constants (and so in the generated `rules.md`) — `own value, unverified` in the doc comment.

## How to rebuild

```sh
git clone --depth 1 https://github.com/yairm210/Unciv.git /path/to/Unciv      # read-only
python3 -I tools/import-unciv.py --unciv /path/to/Unciv                      # catalogs, name pools, difficulty levels
cargo run --release --offline -p classic-content --features importer --bin classic-import   # RON + implemented.md
```

Both steps are idempotent. The importer writes `assets/rules/classic/*.ron` (except `handicaps.ron`, which `import-unciv.py` rewrites from Unciv's difficulty levels, and the hand-made `personalities.ron`) and `implemented.md`.
